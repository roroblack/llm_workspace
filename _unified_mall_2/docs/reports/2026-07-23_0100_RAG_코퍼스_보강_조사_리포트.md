# RAG 코퍼스 보강 조사 — 환불·교환 정책 외에 무엇이 더 필요한가

- 일자: 2026-07-23
- 요청: “환불 교환 정책과 소비자법 외에 더 들어가야 할 문서를 조사·정리하고 최종 점검까지 해서 리포트로”
- 방법: 현행 코퍼스 실측 → Codex 논의 → 웹 조사로 법령 사실 검증 → Codex 최종 점검

## 1. 현황 (실측)

`data/docs/`에 실제로 있는 문서는 **4건**뿐이다.

| 파일 | 크기 | 성격 |
|---|---|---|
| `환불교환정책.pdf` | 100KB | **유일한 정책 문서** |
| `loop_safety.txt` | 1KB | 에이전트 루프 안전(개발 참고) |
| `react_agent_overview.txt` | 1KB | ReAct 개요(개발 참고) |
| `tool_design_rules.txt` | 1KB | 도구 설계 규칙(개발 참고) |

즉 **고객·에이전트 문의에 근거로 쓸 수 있는 문서는 환불·교환 1건**이고, 나머지 3건은 개발 문서다.
GraphRAG 정책 그래프(노드 6·엣지 4)도 환불교환정책에서 도출한 것이다.

**결과**: 환불·교환을 벗어난 질문은 대부분 근거를 찾지 못해 abstention된다. 무폴백 설계 덕에
틀린 답을 만들진 않지만, **답할 수 있는 범위 자체가 좁다.**

## 2. 이 서비스라서 특별히 필요한 것

이 프로젝트는 **AI 에이전트를 직접 사용자로 삼는다**(`docs/project_overview.html` §01).
그래서 사람용 쇼핑몰에는 없던 질의가 생긴다.

- “이 데이터를 **인용해도 되는가**, 재배포·상업 이용이 허용되는가?”
- “에이전트가 **사용자를 대리해 승인**할 수 있는 범위는 어디까지인가?”
- “이 값은 **언제 기준**이며 지금도 유효한가?”
- “AI가 내린 판단을 **거부하고 사람 검토를 요구**할 수 있는가?”
- “봇/API로 접근할 때 허용 한도와 금지 행위는?”

이 질문들은 **라이선스·대리권·최신성·자동화 결정·봇 정책** 문서가 없으면 답할 수 없다.

## 3. 보강 문서 우선순위 (Codex 논의 결과)

| 순위 | 문서 | 답할 수 있게 되는 질의 |
|---|---|---|
| **1** | **거래·결제·배송·취소 통합정책** | 가격·재고 확정 시점, 승인 후 취소 가능 여부, 배송 지연 책임, **명시 승인·대리권 범위**, `Idempotency-Key` 의미, 중복·실패 결제 처리 |
| **2** | **상품정보·보증·분쟁해결 정책** | 사양 근거, 호환성 주장의 출처, 제조사 보증 범위, 하자 판정, **소비자분쟁해결기준**상 보상 기준 |
| **3** | **판매자·플랫폼 역할·책임 정책** | 직매입 / 중개 / 외부 Provider 구분, **계약 당사자가 누구인지**, 문의·피해구제 창구 |
| **4** | **개인정보·보안·자동화된 결정 정책** | 얼굴·음성·영상 처리 목적·보유기간·삭제, 로그 범위, 제3자 제공, **AI 결정 거부·설명 요구 절차** |
| **5** | **데이터 출처·라이선스·인용 정책** | 원출처, 수집일, 허용 용도, 재배포·상업 이용, 변경 이력, 검증 방법 ← **에이전트에게 가장 실질적** |
| **6** | **봇·API·MCP/A2A 이용약관** | 인증, 도구 allowlist, 호출 한도, 크롤링 허용 범위, 대리 승인, 금지 행위, 감사 로그 |
| **7** | **광고·추천·평판 산정 정책** | 협찬 표시, 순위 산정 기준, 측정 기간, 오류 정정 절차 |
| **8** | **서비스 이용약관 · 사업자정보/고객고지** | 서비스 범위·이용 조건·면책, 사업자 표시 의무 항목, 고객센터·분쟁 창구 안내 (Codex 추가 지적) |

우선순위 근거: 1~3은 **이미 구현된 거래 흐름**을 설명하는 문서라 즉시 인용 가치가 있고,
4~6은 **AI가 고객이라는 이 프로젝트 특성**에서 반드시 필요해진 것들, 7~8은 평판·대외 고지가 붙을 때 필요하다.

### 3-1. 문서 집합 자체의 규칙 (Codex 추가 지적)

문서가 8종으로 늘면 **문서끼리 충돌**한다. 근거 기반 답변에서 이건 치명적이므로 코퍼스에 다음을 함께 정의한다.

- **우선순위 규칙**: 예) 법령 > 개별 상품 고지 > 통합정책 > FAQ. 어떤 문서가 이기는지 명시한다.
- **폐기·대체 이력**: 문서가 개정되면 구 버전을 지우지 않고 `superseded_by`로 연결한다.
  낡은 문서가 조용히 검색되어 답에 섞이는 것이 가장 위험하다.
- **문서 단위 메타**: `valid_from` · `review_by` · `supersedes` / `superseded_by` · `source_url` · `collected_at`

## 4. 법령 관련 — 검증한 사실과 위험

### 4-1. 웹 조사로 확인한 사실

| 항목 | 확인 내용 |
|---|---|
| **개인정보 보호법 제37조의2**(자동화된 결정에 대한 정보주체의 권리) | 완전히 자동화된 시스템(**AI 포함**)의 결정이 권리·의무에 중대한 영향을 미치면 **거부**할 수 있고, **설명 등을 요구**할 수 있다. 처리자는 정당한 사유가 없으면 적용하지 않거나 **인적 개입에 의한 재처리·설명** 조치를 해야 하고, **기준·절차를 공개**해야 한다. **2024-03-15 시행** |
| **소비자분쟁해결기준** | 공정거래위원회 고시. 소비자기본법 제16조②·시행령 제8조③ 근거. 별표 Ⅰ(대상품목)·Ⅱ(품목별 분쟁해결기준)·Ⅲ(품질보증기간·부품보유기간)·Ⅳ(내용연수)로 구성. 품목별·피해유형별 보상 기준 제시 |

**우리 시스템에 적용될 가능성이 있어 법률 검토가 필요하다**(단정하지 않는다 — Codex 지적).
적용 여부는 기능별로 따로 판단해야 한다:

- 개인정보를 처리하는가
- **완전히** 자동화된 처리인가(사람의 개입 여지가 없는가)
- 그 결과가 이 조항이 말하는 **‘결정’**에 해당하는가
- 정보주체의 **권리·의무에 중대한 영향**을 미치는가 (거부권에는 예외 조건도 따른다)

예컨대 얼굴 2차 인증은 개인정보를 처리하고 접근 허용/차단을 자동으로 가른다는 점에서 **검토 대상에 가깝고**,
일반 상담 답변·상품 추천·지식 검증 판정은 **자동으로 이 조항이 적용된다고 볼 수 없다.**
따라서 정책 문서에는 “해당 여부를 판단한 결과”와 **기준·절차 공개**, **사람 검토 경로**를 쓰되,
법적 해당성 판단 자체는 **전문가 확인을 전제**로 한다.

> ※ 자기 점검: 이 리포트 초안은 “모두 자동화된 결정이므로 직접 걸린다”고 단정했다. 이는 §4-2에서
> 스스로 경고한 “검증 안 된 법적 단정”에 해당해 Codex 지적으로 수정했다.

### 4-2. 위험 — 법령 원문을 코퍼스에 넣을 때

1. **법률 자문 금지**: 우리 답변은 일반 정보다. 답변에 **“법률 자문이 아님”·기준일·전문가 확인 경로**를
   함께 내보내야 한다. 불확실하면 **abstain**한다(이미 구현된 동작).
2. **최신성**: 법령·고시는 개정된다. 원문을 복제해 두면 **낡은 근거로 확신 있게 답하는** 최악의 상태가 된다.
   → 원문 복제 대신 **스냅숏 메타데이터**를 필수로 붙인다:
   `출처 URL · 시행일 · 수집일 · 본문 해시 · 검토 예정일`.
3. **인용 범위**: 조문 전체를 넣기보다 **우리 서비스에 적용되는 부분만** 발췌하고 원문 링크를 남긴다.
4. **관할·적용 범위**: 국내 전자상거래 전제임을 명시한다(해외 판매·국경 간 거래는 범위 밖).

> ※ 전자상거래법 등 개별 법령의 **최근 개정 시행일은 이 리포트에서 확정하지 않았다.** Codex가 참조 URL을
> 제시했으나 시행일을 직접 검증하지 못했으므로, 코퍼스에 넣기 전 `law.go.kr` 원문으로 확인이 필요하다.
> 검증 안 된 날짜를 문서에 박는 것이 바로 §4-2에서 경고한 실패다.

## 5. 우리 시스템에 붙일 때의 실행 방안

기존 구현을 그대로 활용할 수 있다.

| 필요 | 이미 있는 것 |
|---|---|
| 문서별 출처·위치 인용 | RAG 인용 규약(`source`·`locator`) |
| 근거 없으면 답하지 않음 | abstention → 지식갭 큐 |
| 인용이 원문과 일치하는지 | 바운티 L1 **인용 대조**(문자 수준) |
| 낡은 근거 탐지 | ✗ **없음** — 스냅숏 메타(`시행일`·`검토예정일`) 기반 **만료 경고**가 필요하다 |
| 정책 간 관계 질의 | GraphRAG(노드/엣지 + 재귀 CTE) — 문서가 늘면 가치가 커진다 |

**신규로 필요한 것 하나**: 근거에 `valid_from`/`review_by`를 붙이고, 만료된 근거로 답할 때
**답변을 막거나 경고를 붙이는** 게이트. 지금은 낡은 문서와 최신 문서를 구분하지 못한다.

## 6. 최종 점검 결과 (Codex)

Codex 검토에서 확인된 지적을 반영했다.

- 법령은 **원문 복제보다 스냅숏 관리**(시행일·URL·수집일·해시·검토예정일) → §4-2에 반영
- 답변에 **법률 자문 아님·기준일·전문가 확인 경로** 표시, 불확실하면 abstain → §4-2에 반영
- 소비자분쟁해결기준은 **일반기준과 품목별기준이 구분**됨 → §4-1에 반영
- 자동화된 결정에는 **거부·설명 요구**가 걸릴 수 있음 → §4-1에서 우리 시스템 적용 지점 명시

## 7. 한계 (정직 기록)

- 이 리포트는 **조사·설계 문서이며, 실제 문서를 작성해 코퍼스에 넣지는 않았다.**
- 개별 법령의 최신 개정·시행일은 **미검증**(§4-2 주석). 확인 없이 인용하면 안 된다.
- 우선순위는 이 프로젝트 맥락 기준 판단이며, 실제 문의 로그로 검증된 것이 아니다.
  지식갭 큐가 쌓이면 **실제 질문 분포로 우선순위를 재조정**해야 한다.
- 법률 해석이 필요한 부분은 전문가 확인이 필요하다. 이 리포트는 법률 자문이 아니다.

## 8. 다음 작업 제안

1. **1~3순위 문서 작성** — 이미 구현된 거래 흐름을 서술하는 것이라 우리가 직접 쓸 수 있다(법령 인용 최소화)
2. **근거 만료 게이트** 구현 — `valid_from`/`review_by` 메타 + 만료 시 경고·차단
3. 4~6순위 문서는 법령 확인 후 작성
4. 지식갭 큐 데이터가 모이면 우선순위 재검토
