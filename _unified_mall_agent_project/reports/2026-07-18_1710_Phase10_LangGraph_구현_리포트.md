## 1. 착수 전 Codex 설계 의논 (`reports/_codex_phase10_design_review.txt`)
사용자 지시("코덱스랑 의논해서 진행")대로 구현 직전 3건 의논 → 계획 대비 **설계 변경 1건 확정**:
1. **linear 그래프 제외, conditional만 구현.** 계획 '설계'에 "linear+conditional 두 그래프(강의 대응)"라 적혔으나,
   linear(classify→priority→assign, 분기 없음)는 (a)엔드포인트 미사용 (b)미분류에도 계속 진행 → 합의 #3
   무폴백과 정면 충돌 → YAGNI·RULE 위반. Codex: "잘못된 경로를 강의용으로 만들지 말고 계획을 변경하라." → plan 갱신.
2. **규칙은 명명된 도메인 정책 상수**(긴급={"불만","환불"}, 팀 매핑 7종 전부). 기본팀 없음, 매핑 누락 → `ValidationErr` 명시 실패.
3. **State에서 error 필드 제거.** 미분류는 정상 수동검토 상태(category="미분류"+action="manual_review"). 실제 예외는 전파.

## 3. 그래프 (조건분기, 무폴백)
```
START → classify → ┬ (유효) → priority → ┬ (긴급) → escalate → END
                   │                     └ (일반) → assign   → END
                   └ (미분류)  → manual_review → END
```
- classify 노드: 기존 `app.prompts.classifier.classify_one` **재사용**(중복 0). chat 주입 가능(테스트/로컬).
- 무폴백(합의 #3): 빈 입력 → `ValidationErr`, LLM 연결 실패 → `InfraError` (classify_one이 이미 전파).
  LLM 출력이 허용 카테고리 아님 → `미분류` → **manual_review → END**(priority로 계속 진행 금지).
- 규칙 노드(priority/assign/escalate)는 순수 함수(LLM 무관).
