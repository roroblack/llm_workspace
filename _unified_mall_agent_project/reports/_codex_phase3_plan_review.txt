# RULE.md — 통합 프로젝트 작업 규칙

> 이 문서는 `_unified_mall_agent_project`에서 수행되는 **모든 작업(사람/AI 에이전트 공통)**에 적용되는 최상위 규칙이다.
> 어떤 지시·계획·리포트도 이 문서와 충돌하면 이 문서가 우선한다.

---

## 1. 할루시네이션(환각) 방지 규칙

### 1.1 근거 없는 주장 금지
- 코드, 파일, API, 라이브러리 동작에 대해 서술할 때는 **반드시 실제 파일을 읽거나 실행해서 확인한 후** 서술한다.
- 확인하지 않은 내용은 "확인 필요"라고 명시하고, 추측을 사실처럼 쓰지 않는다.
- 파일 경로·함수명·클래스명을 인용할 때는 실제 존재를 확인하고 `경로:줄번호` 형식으로 남긴다.

### 1.2 검증 우선 원칙
- 코드 변경 후에는 **실행 또는 테스트로 동작을 검증**하고, 검증 결과(성공/실패 로그)를 리포트에 그대로 기록한다.
- 테스트가 실패하면 실패했다고 정직하게 기록한다. "아마 될 것이다"류의 서술 금지.
- 외부 라이브러리 버전·API 시그니처는 requirements.txt 또는 실제 설치 환경에서 확인한다.

### 1.3 출처 표기
- 레거시 프로젝트에서 가져온 코드는 **원본 프로젝트명과 파일 경로를 주석 또는 리포트에 명시**한다.
- 문서 작성 시 참조한 파일/리포트를 문서 하단 "참조" 절에 나열한다.

## 2. 하네스(Harness) 작업 규칙

모든 작업 세션은 아래 루프를 따른다.

```
[작업 시작]
 1. plans/ 에서 현재 유효한 계획서를 읽는다
 2. history/ 최신 이력을 읽고 직전 작업 상태를 파악한다
[작업 수행]
 3. 계획서의 해당 단계만 수행한다 (계획에 없는 작업은 계획서 갱신 먼저)
 4. 변경 전 코드를 대체/삭제하는 경우 legacy/ 에 보존한다
 5. 변경 후 실행/테스트로 검증한다
[작업 종료]
 6. reports/ 에 작업 리포트를 제출한다 (필수, 생략 불가)
 7. history/ 에 작업 이력을 추가한다
 8. 계획 진행 상태가 바뀌면 plans/ 문서를 갱신한다
```

- 한 세션에서 **계획서에 정의된 범위를 초과하는 작업을 하지 않는다.** 범위 변경이 필요하면 먼저 계획서를 수정하고 사유를 기록한다.
- 작업 단위는 "검증 가능한 최소 단위"로 쪼갠다. 한 번에 여러 기능을 섞어 작업하지 않는다.

## 3. 구현 원칙

### 3.1 하드코딩 금지
- API 키, 모델명, 경로, DB 접속 정보, 매직 넘버를 소스 코드에 직접 쓰지 않는다.
- 설정은 `.env` + `config` 모듈(pydantic-settings)로 일원화한다.
- 예외: 테스트 코드의 고정 입력값, 상수 모듈에 이름 붙여 선언한 상수.

### 3.2 폴백(fallback) 금지
- 오류를 삼키고 임의의 기본 동작으로 대체하는 코드를 작성하지 않는다.
- API 키 부재, 파일 부재, DB 연결 실패 등은 **명시적 예외를 발생시키고 명확한 오류 메시지로 실패**시킨다.
- "키 없으면 데모 응답", "실패하면 빈 값 반환" 같은 레거시 패턴은 이관 시 제거한다.
- 예외: 사용자에게 오류를 안내하는 HTTP 오류 응답(4xx/5xx)은 폴백이 아니라 정상 오류 처리다.

### 3.3 꼭 필요한 부분만 구현 (YAGNI)
- 계획서에 명시된 기능만 구현한다. "나중에 쓸 것 같은" 코드, 사용되지 않는 옵션, 죽은 코드를 만들지 않는다.
- 레거시 프로젝트 이관 시 **학습 가치가 검증된 핵심 로직만** 가져오고, 중복 스캐폴딩은 버린다.
- 같은 기능의 두 구현이 생기면 즉시 하나로 통합하고 나머지는 legacy/로 보낸다.

### 3.4 리포트 제출 의무
- **모든 작업 세션은 reports/ 에 리포트 파일 제출로 종료된다.** 리포트 없는 작업은 완료로 인정하지 않는다.
- 리포트에는 최소한 다음을 포함한다:
  1. 작업 목표 (어느 계획서의 어느 단계인지)
  2. 실제 수행 내용 (변경 파일 목록 포함)
  3. 검증 방법과 결과 (실행/테스트 로그 원문 요약)
  4. 미해결 이슈·다음 작업 제안

## 4. 폴더별 문서 규칙

| 폴더 | 용도 | 갱신 시점 |
|---|---|---|
| `plans/` | 작업 계획서. 단계별 목표·범위·완료 기준 정의 | 새 작업 착수 전 / 범위 변경 시 / 단계 완료 체크 시 |

| `legacy/` | 대체·폐기된 코드와 문서의 보존소 | 기존 코드를 대체/삭제하기 직전 |

- legacy/ 보존 시 원본 위치를 알 수 있게 한다: `legacy/<원본프로젝트명>/<원본경로>` 구조 유지.

### 4.2 history 기록 형식
```markdown
## YYYY-MM-DD HH:mm — <작업 제목>
- 계획: <plans/ 문서명> 의 <단계>
- 수행: <핵심 변경 요약>
- 검증: <성공/실패 + 방법>

```

"""주문 서비스: 생성(재고검증·스냅샷·합계·재고차감) / 조회.

주문 생성 + 재고 차감 + 주문항목 저장은 한 트랜잭션(한 commit)으로 처리한다
(Codex 합의: 원자성).

from __future__ import annotations

import uuid

from sqlalchemy.orm import Session

from app.core.errors import ForbiddenErr, NotFoundErr, ValidationErr
from app.db.models import Inventory, Order, OrderItem, Product, User


def _new_order_no() -> str:
    return "O" + uuid.uuid4().hex[:11].upper()


def create_order(db: Session, user: User, lines: list[dict]) -> Order:
    """lines: [{"product_code": str, "quantity": int}, ...]"""
    order = Order(order_no=_new_order_no(), user_id=user.id, status="PENDING", total_amount=0)
    total = 0
    try:
        for line in lines:
            code = line["product_code"]
            qty = int(line["quantity"])
            if qty <= 0:
                raise ValidationErr("수량은 1 이상이어야 합니다.")

            product = db.query(Product).filter(Product.product_code == code).first()
            if product is None:
                raise NotFoundErr(f"상품을 찾을 수 없습니다: {code}")

            inv = db.query(Inventory).filter(Inventory.product_id == product.id).first()
            available = inv.stock if inv else 0
            if available < qty:
                raise ValidationErr(
                    f"재고 부족: {product.name} (요청 {qty}, 재고 {available})"
                )

            # 주문시점 단가/상품명 스냅샷
            order.items.append(
                OrderItem(
                    product_id=product.id,
                    product_name=product.name,
                    unit_price=product.price,
                    quantity=qty,
                )
            )
            total += product.price * qty
            inv.stock -= qty  # 재고 차감

        order.total_amount = total
        db.add(order)
        db.commit()  # 주문+항목+재고차감 원자적 커밋
        db.refresh(order)
        return order
    except Exception:
        db.rollback()
        raise


def list_orders(db: Session, user: User) -> list[Order]:

def pay_order(db: Session, user: User, order_no: str, method: str) -> Payment:
    order = db.query(Order).filter(Order.order_no == order_no).first()
    if order is None:
        raise NotFoundErr("주문을 찾을 수 없습니다.")
    if order.user_id != user.id:

            method=method,
            status="PAID",
        )
        order.status = "PAID"
        db.add(payment)
        db.commit()  # 결제+주문 PAID 원자적 커밋
        db.refresh(payment)
        return payment
    except Exception:
        db.rollback()
        raise
