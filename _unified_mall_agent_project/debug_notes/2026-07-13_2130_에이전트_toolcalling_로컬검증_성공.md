## 근본 원인: `tool_choice` 누락 (실제 버그)

`react.py`의 `_default_chat_fn`이 `tools=`만 보내고 **`tool_choice`를 보내지 않았다.**
OpenAI SDK는 `tool_choice`를 기본으로 전송하지 않는데, **llama-cpp의
`chatml-function-calling` 핸들러는 `tool_choice`가 있어야 도구 호출을 활성화**한다.

격리 검증(같은 모델·같은 프롬프트·같은 tools):
```
tool_choice 없음        -> tool_calls: False   (모델이 <think> 추론 후 텍스트로만 답변)
tool_choice='auto'      -> tool_calls: ['get_price']  ✓
tool_choice='auto' + max_tokens 유/무 -> 둘 다 ✓ (max_tokens는 무관)
```

**수정**: `react.py`에 `tool_choice="auto"` 명시.
실제 OpenAI/Gemini에서는 `auto`가 기본값이라 **무해**(동작 동일).

## 교훈 (공략집 반영)
- OpenAI 호환 서버라고 다 같지 않다. `tools`만 보내면 되는 곳도 있고,
  **`tool_choice`를 명시해야 도구 호출이 켜지는 구현**도 있다.
- 로컬 모델로 tool-calling을 검증하면 이런 호환성 버그를 **키/토큰 없이** 잡을 수 있다.
