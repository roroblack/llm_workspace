## 1. 목표
SQLite 기반 DB + JWT 인증 + 상품/주문/결제 CRUD. 에이전트 도구(Phase 3)가 조회할 실 데이터 계층.

## 2. 설계 결정 (기록)
- **DB: SQLite 확정** (v2 §8). `DATABASE_URL`로 MySQL 전환 가능하게 SQLAlchemy 사용.
- **카탈로그 엔티티: Product** (계획서 초안의 "Menu"는 board_mysql 유산). 이유: 이관된 실데이터가 `products.csv`(product_id/name/category/price) + `inventory.csv`이고, 승승장구몰은 전자제품 쇼핑몰이라 Product가 정확. → v2 문구의 Menu를 Product로 정정(사유 명시).

## 4. 모델 (SQLAlchemy 2.0)
- **User**(id, username unique, hashed_password, created_at)
- **Product**(id, product_id unique, name, category, price)
- **Inventory**(id, product_id FK unique, stock, reorder_level, warehouse)
- **Order**(id, order_no unique, user_id FK, status[PENDING/PAID], total_amount, created_at)
- **OrderItem**(id, order_id FK, product_id FK, product_name 스냅샷, unit_price 스냅샷, quantity)
- **Payment**(id, order_id FK unique, amount, method, status[PAID], created_at)

## 5. 인증
- `passlib[bcrypt]` 해싱, `python-jose[cryptography]` JWT(HS256), `OAuth2PasswordBearer`
- **SECRET_KEY는 config(.env)에서** (하드코딩 금지). 기본값은 개발용 표시 + 운영 시 필수 교체 주석
- `get_current_user`: 토큰 검증 실패 → 401

## 6. 비즈니스 규칙 (폴백 금지)
- 주문: 상품 존재·재고 충분 검증 → 부족 시 `ValidationErr`(422). 주문시점 단가/상품명 스냅샷. 합계 계산.
- 결제: 주문 존재·본인 소유(아니면 403)·중복결제 아님 검증 → 위반 시 명시적 오류(빈 응답/무시 없음).
- 재고 차감: 주문 성공 시 Inventory.stock 감소.

## 7. 시딩
- `db/seed.py`: products.csv → Product, inventory.csv → Inventory(product_name으로 매칭). 멱등(이미 있으면 skip). 앱 시작 시 또는 명령으로 실행.
- orders.csv는 user 없는 데모라 시딩 제외(주문은 API로 생성). 사유 기록.

## 8. 의존성 추가 (버전은 설치 후 실제값 고정)
- sqlalchemy, passlib[bcrypt], bcrypt(호환 버전), python-jose[cryptography], python-multipart

## 11. Codex 합의 반영 (조건부 GO → 반영 완료)
1. **SECRET_KEY**: config에 `SECRET_KEY|None`, `JWT_ALGORITHM`, `ACCESS_TOKEN_EXPIRE_MINUTES` 추가. auth 사용 시 미설정이면 `require_secret_key()`가 ConfigError. (레거시 `getenv(default="change-this")` 금지) → config.py 반영 완료
2. **트랜잭션 원자성**: 주문 생성+재고차감+주문항목 = 1 commit. 결제+주문 PAID = 1 commit.
3. **네이밍 충돌**: CSV의 상품코드는 `Product.product_code`(=P0001), 관계 FK는 `product_id`(정수 PK). Inventory.product_id = FK.
4. **결제 금액 서버계산**: `PaymentCreate`는 order_id·method만, 금액은 주문 합계에서 서버가 계산.
5. **seed 명시적 오류**: product_name 매칭 실패/중복은 조용히 skip 금지 → 오류 또는 로그+집계 후 리포트.
6. **DATABASE_URL 절대경로**: ROOT_DIR 기반 → config.py 반영 완료.
7. **auth 예외 구조화**: `AuthErr(401)`, `ForbiddenErr(403)`, `NotFoundErr(404)` 추가 → errors.py 반영 완료.
8. **추가 테스트**: 중복결제, 무효/만료 토큰, seed 멱등성.
9. **v2 Menu→Product 정정** → v2 반영 완료.
