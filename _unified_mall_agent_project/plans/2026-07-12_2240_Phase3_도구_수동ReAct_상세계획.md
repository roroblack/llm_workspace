## 3. 도구 (PDF6 좋은 도구 5원칙 + 구조화 실패관찰)
- `get_price(db, product_code)` → {ok, product_name, price}
- `get_stock(db, product_code)` → {ok, product_name, stock, reorder_level, need_reorder}
- `get_order_status(db, order_no)` → {ok, order_no, status, total_amount}
- `search_product(db, keyword)` → {ok, results:[{code,name,price}]}  (키워드 부분검색)
- `get_exchange_rate(db, currency)` → {ok, currency, rate}  (고정 환율표 상수, 외부호출 없음)
- 각 도구: 한 가지 일, 명확한 인자, 구체적 독스트링(모델 프롬프트), 일관된 dict 반환
- **오류처리**: 내부 예외를 `{"ok": false, "error_code", "message"}` 구조화 관찰로 변환 (정상결과 위장 금지, §6)
- `TOOLS_SCHEMA`(OpenAI function 스키마 리스트), `TOOL_MAP`(name→callable)

## 4. 수동 ReAct 루프 (react.py)
- `run_react_agent(question, db, chat_fn=None, max_steps=3, system_prompt=None)`
  - `chat_fn`: (messages, tools) → assistant message dict. 기본은 실제 OpenAI 클라이언트, 테스트는 mock 주입
  - messages = [system, user], 루프 max_steps:
    1. `msg = chat_fn(messages, TOOLS_SCHEMA)`
    2. tool_calls 없으면 → 최종답변 반환(stopped_by=final_answer)
    3. 각 tool_call: **중복 서명(name+정렬인자) 차단**(반복 시 stopped_by=duplicate) → `TOOL_MAP[name](db, **args)` 실행 → 결과를 tool 메시지로 append
    4. **history trim**(head 2 + tail N)
  - max_steps 소진 → stopped_by=max_steps
  - 각 단계 AgentStep(thought/action/observation) 기록
- **키 부재/프로바이더 오류는 ConfigError**(폴백 없음). 로컬 서버 미기동 시 실호출 경로는 APIConnectionError → 502 매핑 검토

## 5. 라우터
- `POST /api/agent/chat` {question, max_steps?} → {answer, steps[], stopped_by}
- LLM 실호출이므로 기본 provider=local. 서버 미기동 시 명확한 오류.

## 6. 테스트 전략
- **test_tools**: 실 DB로 각 도구 정상/오류(없는 상품→ok:false) — 결정론적
- **test_react_agent**: mock chat_fn이 스크립트대로 tool_call 후 최종답변 반환 → 루프가 도구 실행·관찰·종료하는지. max_steps 초과, 중복호출 차단, 없는 도구 처리 케이스 — **모델 없이 결정론적**
- **test_react_live**(@pytest.mark.llm, CI 제외): 로컬 Gemma로 실제 1~2스텝, 답변 문자열 존재만 확인(내용 비결정적이라 느슨하게)

## 7. DoD
1. pytest(mock 포함) 전부 pass — 도구·루프 로직 결정론적 검증
2. 중복호출 차단·max_steps·도구 오류 관찰 테스트 pass
3. (수동) 로컬 Gemma 스모크: `/api/agent/chat`가 도구 결과 반영 답변 생성 — 로그 캡처
4. reports/history/진행표 갱신

## 9. Codex 합의 반영 (조건부 GO)
1. 도구 5개 유지 (8개 확장 금지, YAGNI).
2. **비즈니스 실패만 {ok:false} 구조화 관찰**(없는 상품/주문 등). **인프라 실패(DB/설정/LLM서버 다운)는 삼키지 말고 InfraError/LLM오류로 raise** → 도구는 broad try/except로 전부 감싸지 않고, 예상된 조건만 명시 체크.
3. ReAct: **assistant 메시지(tool_calls 포함)를 tool 결과보다 먼저 append**(OpenAI 순서). 중복서명=`name + json.dumps(args, sort_keys=True)`. **args JSON 파싱 실패 케이스 테스트**. trim은 assistant/tool 쌍을 깨지 않게.
4. 로컬 Gemma tool-calling은 비필수 스모크(@pytest.mark.llm), mock 테스트가 필수 DoD.
5. 구현 순서: 도구→도구테스트→루프/mock테스트→라우터→오류매핑→스모크.
