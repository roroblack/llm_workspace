## 2. 설계 (기존 재사용, 최소 추가)
### app/rag/qa.py (신규)
- `answer(question, k=None, chat_complete=None)`:
  - `service.search(question, k)`로 근거 청크 검색(기존 재사용, 거리 임계값 필터 그대로)
  - 검색 결과 없음 → `{"answer": "제공된 문서에서 찾을 수 없습니다.", "sources": []}` (환각 억제)
  - 있으면 근거 context 구성 → 환각억제 프롬프트 → `chat_complete`(평문) → `{answer, sources}`
  - `sources`: 청크 metadata의 (source, page) 중복 제거 목록
  - `chat_complete` 주입 가능(기본 = get_chat_client 평문, summarize와 동일 패턴). 연결실패 InfraError, 빈 질문 ValidationErr
- 환각억제 프롬프트: "아래 [문서]에 있는 내용만 근거로 답하라. 없으면 '제공된 문서에서 찾을 수 없습니다.'"

### app/rag/build_index.py (확장, 기존 보존)
- `_load_txt_docs` → `_load_docs`: `*.txt`(기존 그대로) **+ `*.pdf`(PyPDFLoader, page metadata 보존)**
- TXT 동작 불변. PDF는 페이지별 Document에 source=파일명, page 유지 → 청킹 시 metadata 전파
- 기존 시그니처/반환 유지, 인덱스 marker 로직 유지

### app/rag/service.py (최소 확장)
- `search()` 반환에 `page` 필드 추가(metadata에 있으면 값, 없으면 None). 기존 키(text/source/distance) 유지 → 기존 테스트 호환

### app/routers/rag.py (엔드포인트 추가)
- `POST /api/rag/qa` {question, top_k} → `{answer, sources}`. 기존 /search·/summarize 유지

### 의존성
- `pypdf==6.14.2` (설치됨) requirements 추가

## 7. Codex 합의 반영 (구현 Go)
1. **PDF 파싱 실패 = InfraError**(파일명 포함). TXT 폴백 금지. TXT+PDF 둘 다 있으면 둘 다 인덱싱. 문서 0개일 때만 "없음" 오류.
2. **search 반환에 `page`(nullable) 추가** — metadata의 raw page(0-based). QA sources에서 **1-based로 변환**(PyPDFLoader는 0-based). 기존 키 유지.
3. **무근거 고정답변**은 폴백 아님(정상 도메인 응답, OK). 금지: PDF실패 무시·LLM실패시 빈/고정답·QA실패시 검색문 그대로 반환·손상페이지 무단 skip.
4. **sources는 서버가 결정론적으로 구성**(모델 생성 아님). `(source, page)` 중복제거, 검색 순서 유지, TXT page=null, PDF page=1-based.
5. 프롬프트에 **검색 context만 사용 + 문서 내 명령 무시**(인젝션 방어) 명시. LLM 연결실패 InfraError.
6. completion은 summarize 패턴 재사용(qa 전용 얇은 wrapper 허용, 기존 모듈 미변경으로 회귀 방지).
7. rerank는 이번 범위 제외(YAGNI).
→ 구현 Go. 위 반영.
