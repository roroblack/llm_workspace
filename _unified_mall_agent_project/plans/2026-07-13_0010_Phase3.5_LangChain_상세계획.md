## 1. 목표
Phase 3 수동 ReAct와 동일한 도구를 LangChain으로 자동화. 강의의 "수동→프레임워크" 2단계 완성.

## 2. YAGNI 방침 (v2 §3.5, Codex 합의)
- 수동 ReAct(Phase 3)는 **학습·비교 baseline**으로 동결(코드 유지).
- LangChain 계층을 운영 경로 후보로 추가.
- **수동 vs LangChain 1회 대조 + 운영 경로 단일화는 로컬 Gemma로 불가** → 최종 실키 스모크에서 대조·확정. 그 전까지는 두 경로 병존, 라우트로 구분.

## 3. 산출 파일
```
app/core/llm_clients.py   # get_langchain_chat(provider) 추가 (ChatOpenAI/ChatGoogleGenerativeAI)
app/agent/lc_tools.py     # 커머스 도구 5종을 LangChain @tool로 (db 클로저 바인딩, commerce_tools 재사용)
app/agent/lc_agent.py     # create_agent 기반 자동 ReAct → AgentResponse 형태로 steps 추출
app/routers/agent.py      # POST /api/agent/lc-chat 추가 (수동은 /api/agent/chat 유지)
tests/test_lc_tools.py    # @tool 구성·실행(구조/결정론)
tests/test_lc_agent.py    # 에이전트 구성 + mock 모델로 흐름(가능 범위), 실모델은 @llm
```

## 4. 설계
### get_langchain_chat(provider)
- local/openai → `ChatOpenAI(base_url=..., api_key=..., model=...)` (local은 base_url=LOCAL, api_key=dummy)
- gemini → `ChatGoogleGenerativeAI(model=..., google_api_key=...)`, 키 없으면 ConfigError
- 폴백 없음. 미설정 시 ConfigError.

### lc_tools.build_tools(db)
- commerce_tools의 순수 함수를 재사용. `@tool` 데코레이터로 감싼 5개를 db 클로저로 바인딩해 리스트 반환.
- 도구 반환은 문자열(JSON) — LangChain tool 관례. 내부적으로 commerce_tools 결과를 json.dumps.

### lc_agent.run_langchain_agent(question, db, model=None, max_steps 제한)
- `from langchain.agents import create_agent` (LangChain 1.x) 또는 langgraph `create_react_agent`
- model = get_langchain_chat() (기본 local)
- 실행 후 메시지에서 tool 호출/결과를 AgentStep으로 추출, AgentResponse 반환
- recursion/step 제한 설정. LLM 연결 실패 → InfraError.

## 5. 테스트
- test_lc_tools: build_tools(db)가 5개 BaseTool 반환, 각 .invoke({...})가 commerce_tools와 동일 결과(JSON) — 결정론적, 모델 불필요
- test_lc_agent: 에이전트 객체 생성 성공(구조). 가능하면 FakeListChatModel 등 mock 모델로 tool 호출 흐름 1건. 실모델 경로는 @pytest.mark.llm
- **필수 DoD = 구조/도구 결정론 테스트.** 라이브는 최종 실키.
