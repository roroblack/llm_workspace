워크스페이스 28개 실습 프로젝트의 학습 성과를 **하나의 실행 가능한 프로젝트**로 통합한다.

**완성 기준 (Definition of Done)**
- FastAPI 단일 앱에서 ReAct 에이전트가 커머스 도구·RAG·ML 분류를 활용해 사용자 요청을 처리한다.
- 레거시의 데모 모드/폴백/하드코딩이 모두 제거된 상태다.

## 3. 단계별 계획

### Phase 0 — 거버넌스 구축 ✅ (2026-07-12 완료)

### Phase 1 — 뼈대 구축
**범위**: 실행 가능한 최소 앱 골격
1. `app/core/config.py` — pydantic-settings 단일 설정 (레거시 common.py 6종 대체)
2. `app/core/llm_clients.py` — OpenAI/Gemini 프로바이더 추상화 (폴백 없음, 키 부재 시 명시적 예외)
3. `app/main.py` + health 라우터 + 정적 UI 자리
4. `data/` — 승승장구몰 데이터셋 단일본 이관 (콘솔 프로젝트들의 CSV 중복 제거)
5. `tests/` — config·clients 단위 테스트
- **완료 기준**: `uvicorn` 기동 + `/api/health` 200 + pytest 통과 로그를 리포트로 제출

### Phase 2 — DB·인증·커머스 코어
**범위**: board_mysql/coffee의 CRUD 흡수
1. SQLAlchemy 모델(User/Menu/Order/OrderItem/Payment) 이관 — MySQL 또는 SQLite 선택은 착수 시 결정·기록
2. JWT 인증(auth 라우터), 주문/결제 서비스 계층
3. 데이터 시딩 스크립트 (CSV → DB)
- **완료 기준**: 회원가입→로그인→주문→결제 E2E 시나리오 검증 로그

### Phase 3 — 도구 계층 + ReAct 에이전트
**범위**: react/agent_loop/function_calling/tool_system 흡수
1. `tools/` — DB 기반 커머스 도구 5종+ (재고/가격/주문상태/상품검색/환율)
2. `agent/react.py` — ReAct 루프 (max_steps, 중복호출 차단, history 트리밍, 토큰 추적)
3. `/api/agent/chat` 엔드포인트 + 단계 로그(thought/action/observation) 반환
- **완료 기준**: 복합 질문("A상품 재고와 주문 상태 알려줘") 도구 2개 이상 연쇄 호출 검증

### Phase 4 — 프롬프트·Planning 모듈
**범위**: prompt/cot/planning 콘솔 흡수
1. `prompts/` — 역할, few-shot 분류, JSON 강제, 인젝션 방어, CoT+자기검증 템플릿
2. `agent/planning.py` — Pydantic Plan + 검증→재계획, 에이전트와 연동
- **완료 기준**: CS 문의 분류 정확도 측정 리포트 + 계획 생성/재계획 검증

### Phase 5 — RAG·문서 처리
**범위**: vector_db/langchain_test/react vector 흡수
1. `rag/` — 청킹, 임베딩(실 제공자만, 해시 폴백 제거), FAISS 또는 Chroma 영속화(선택 근거 기록), 메타필터, 증분 추가
2. PDF 업로드 요약(map-reduce) 라우터
3. 에이전트에 `search_knowledge_base` 도구로 연결
- **완료 기준**: 정책 문서 질문 → 근거 문서 인용 답변 검증

### Phase 6 — ML 분류 서비스
**범위**: coffee/survey 의도분류, Bert_sentiment/NAVER/BBC 학습 성과 흡수
1. `ml/intent.py` — 의도분류 (1차: PyTorch MLP 이관, 2차: KoELECTRA 업그레이드 여부는 별도 계획으로)
2. `ml/sentiment.py` — 리뷰 감성분석 (Bert_sentiment 학습 모델 재사용)
3. 에이전트 전처리 단계(라우팅) 또는 도구로 연결
- **완료 기준**: 의도/감성 분류 정확도 측정 리포트

### Phase 7 — 실험실·UI·마무리
**범위**: llm_parameter 2종/chatgpt 설정/usage 흡수
1. `lab/` — 파라미터 실험 라우터 (basic/role/diversity/token-compare)
2. `static/` 챗 UI — 멀티턴 세션, 설정 패널, 에이전트 단계 시각화
3. 워크스페이스 README 갱신, 레거시 프로젝트 처리 방침 확정(보존/삭제는 사용자 결정 사항)
- **완료 기준**: 전 기능 수동 E2E 점검 리포트 + 최종 통합 리포트

## 4. 단계 공통 규칙 (RULE.md 요약 적용)

- 각 Phase는 **착수 전 계획 확인 → 수행 → 검증 → reports/ 리포트 → history/ 기록** 루프를 따른다.
- 레거시 코드 이관 시 원본 출처(프로젝트/파일)를 주석·리포트에 명시한다.
- 이관 과정에서 대체되는 실험적 코드는 `legacy/`에 보존한다.
- 데모 모드·폴백·하드코딩은 이관 시점에 제거한다.
- 한 Phase 안에서도 작업 세션 단위로 리포트를 쪼개 제출할 수 있다 (권장).
