## 2. 핵심 설계 결정 (기록)
- **임베딩 = 로컬 sentence-transformers `jhgan/ko-sroberta-multitask`** (실제 임베딩 모델, HF캐시에 있음, 토큰0). **해시 폴백 제거**(RULE §7). openai/gemini 임베딩은 옵션(키 필요, 이월).
- **벡터스토어 = FAISS** (langchain-community FAISS 래퍼: save_local/load_local, similarity_search_with_score). 이유: PDF4가 FAISS 영속화·거리점수를 강조. Chroma는 미채택(사유 기록).
- **인덱싱/서비스 분리**: `build_index.py`(사전 1회) ↔ `service.py`(로드 1회, 요청은 검색만). "요청마다 from_documents" 안티패턴 회피.
- **FAISS 점수 = 거리**(작을수록 유사, 코사인 반대) — 주석·테스트로 명시.

## 4. 설계 상세
### embeddings.py
- `EMBEDDING_PROVIDER = local_st | openai | gemini` (config, 기본 local_st)
- local_st → `HuggingFaceEmbeddings(model_name=ST_EMBEDDING_MODEL)` (ko-sroberta)
- openai/gemini → 키없으면 ConfigError

### build_index.py
- `build_index(docs_dir, out_dir)`: txt 로드 → `RecursiveCharacterTextSplitter` 청킹 → `FAISS.from_documents(chunks, embeddings)` → `save_local(out_dir)`. metadata에 source 포함.
- 멱등: out_dir 있으면 재생성(덮어쓰기) 또는 skip 옵션.

### service.py
- `get_store()`: VECTOR_DIR에서 `FAISS.load_local` **1회 로드 후 캐시**. 없으면 명확한 오류(빌드 먼저).
- `search(query, k=3, source=None)`: `similarity_search_with_score` → [{text, source, score(거리)}], 거리 오름차순. source 메타필터.
- `add_documents(texts, sources)`: 증분 `add_documents` + save_local.

### summarize.py
- `summarize_text(text, chat_complete=None)`: 길면 청크분할 → 청크별 요약(map) → 통합(reduce). 로컬 Gemma 평문.

### search_knowledge_base 도구
- `search_knowledge_base(db, query)` → rag.service.search 결과를 {ok, results} 구조화. (db 인자는 시그니처 일관성용, 미사용 가능)
- 에이전트 TOOLS에 추가 (6번째 도구) — 단 도구 5개 유지 원칙과 상충? → search_knowledge_base는 RAG 연결이라 별도. 도구 6개로 확장(정당한 신규 기능).
