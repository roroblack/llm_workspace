## 3. 파일별 사양

### config.py (pydantic-settings)
- `LLM_PROVIDER: Literal["local","openai","gemini"] = "local"`
- 로컬: `LOCAL_BASE_URL="http://127.0.0.1:8000/v1"`, `LOCAL_MODEL="gemma-4-e4b"`, `LOCAL_API_KEY="not-needed"`
- OpenAI: `OPENAI_API_KEY: str|None`, `OPENAI_MODEL="gpt-4o-mini"`, `OPENAI_EMBEDDING_MODEL="text-embedding-3-small"`
- Gemini: `GOOGLE_API_KEY: str|None`, `GEMINI_MODEL="gemini-2.5-flash"`
- 경로: `DATA_DIR`, `DOCS_DIR`, `VECTOR_DIR`, `DATABASE_URL="sqlite:///./data/mall.db"`
- `.env`에서 로드, 모델명·경로 하드코딩 금지(전부 여기 집중)
- `readiness()` 메서드: 각 프로바이더/DB/벡터 준비 여부 boolean dict

### llm_clients.py (폴백 금지)
- `get_chat_client()`: 현재 `LLM_PROVIDER`에 맞는 OpenAI 호환 클라이언트 반환
  - local → `OpenAI(base_url=LOCAL_BASE_URL, api_key=LOCAL_API_KEY)`
  - openai → 키 없으면 `ConfigError` (데모/폴백 절대 없음)
  - gemini → Phase 3.5에서 LangChain 경유(1차는 stub + ConfigError 명시)
- `get_active_model()`: 프로바이더별 모델명
- **키/설정 부재 시 조용한 대체 없이 `ConfigError` raise**

### errors.py (taxonomy)
- `AppError(base)`, `ConfigError`(503), `InfraError`(503), `LLMOutputError`(502), `ValidationErr`(422)
- `register_exception_handlers(app)`: 각 예외 → 정의된 HTTP status + `{ok:false,error_code,message}` JSON

### health.py
- `GET /api/health` → `{status:"ok", provider, readiness:{local,openai,gemini,db,vector}}` (200)
- **⚠️ (Codex 합의) health는 실제 LLM/네트워크 호출 금지.** readiness는 "설정값·키·경로 존재 여부"만 boolean 보고.

### main.py
- `create_app()`: Settings 로드, 예외핸들러 등록, health 라우터 include, 정적 마운트 자리(주석)

### requirements.txt (Phase 1 최소, 버전 고정)
- fastapi==0.116.1, uvicorn[standard]==0.35.0, pydantic==2.11.7, pydantic-settings==2.10.1
- openai==1.99.9 (OpenAI 호환 로컬서버/실OpenAI 공용), python-dotenv==1.0.1
- pytest==8.4.1, httpx==0.28.1 (TestClient)
- (llama-cpp-python은 시스템에 이미 설치, 서버 실행용이라 앱 의존성엔 미포함)

### .env.example
- LLM_PROVIDER=local + 로컬 기본값 + OPENAI_API_KEY= / GOOGLE_API_KEY= (빈칸)

### ci.yml
- push 시 python 3.12 + `pip install -r requirements.txt` + `pytest -q` (LLM 마커 제외)
