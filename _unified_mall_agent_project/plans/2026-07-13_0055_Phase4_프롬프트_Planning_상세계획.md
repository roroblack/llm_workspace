app/prompts/

## 3. 설계
### templates.py (순수 함수, 결정론)
- `CATEGORIES = [결제,환불,상품문의,교환,배송,칭찬,불만]`
- `build_classify_prompt(text, fewshot_examples)` — 카테고리 목록+few-shot 예시+대상 텍스트
- `wrap_user_input(text)` — `<<<`/`>>>` 구분자로 감싸 데이터 영역 격리(인젝션 방어)
- `HARDENED_ROLE` — 보안 규칙 포함 시스템 프롬프트
- `build_cot_prompt(question)` / `should_use_cot(question)` — 단순/함정 질문이면 CoT 끄기 휴리스틱
- JSON 3방식(프롬프트/mime_type/response_schema) 노트 상수

### classifier.py
- `classify_one(text, chat_complete=None)` — chat_complete(prompt)->str 주입 가능(기본 get_chat_client 평문). 출력에서 CATEGORIES 중 하나로 정규화(못 찾으면 '미분류')
- `measure_accuracy(preds, labels)` → {accuracy, wrong:[(idx,label,pred)]}
- `confusion_pairs(preds, labels)` → Counter{(label,pred):n} (혼동쌍 집계, 측정→분석→처방)
- 인프라 실패(연결)는 InfraError 전파

### planning.py
- `Plan(BaseModel)`: goal:str, steps:list[str]
- `validate_plan(plan)` → 단계 2~8개·빈 단계 없음 아니면 ValidationErr
- `make_plan(goal, model=None)` — LangChain `with_structured_output(Plan)` (LLM)
- `replan(goal, reason, model=None)` — 실패사유 피드백 재생성 (LLM)
- `plan_with_validation(goal, make=make_plan, max_replan=2)` — 생성→검증→(실패 시)재계획 루프. make 주입 가능(테스트)

## 7. Codex 합의 반영 (조건부 GO)
1. **classify_one 정규화**: 출력에서 CATEGORIES가 정확히 1개 감지되면 반환, 0개/2개 이상이면 `'미분류'` sentinel. `'미분류'`는 CATEGORIES에 미포함(프롬프트 선택지는 7개), 측정에서만 오답 집계. 빈 입력→ValidationErr, 설정없음→ConfigError, 연결실패→InfraError.
2. **planning 에러**: `goal` 빈값→ValidationErr(422). LLM Plan 단계검증 실패→**내부 재계획**(예외 아님). `max_replan` 초과 후에도 실패→`LLMOutputError(502)`. (validate_plan은 문제목록 반환, plan_with_validation이 루프·최종 LLMOutputError)
3. **few-shot 자동화 범위**: `measure_accuracy`→`confusion_pairs`→`suggest_fewshot_candidates`(보강 후보 산출)까지만. 프롬프트 자동 재작성/반복 튜닝은 YAGNI로 보류.
4. **CoT 휴리스틱**은 학습 데모용(품질 보장 아님). CS 분류는 '라벨만 출력'.
5. **라벨 컬럼 = `category_hint`** 명시.
6. make_plan 라이브는 로컬 Gemma로 조용히 시도 금지 → mock/실키로만.
→ Go. 위 반영 후 착수.
